# Плагин «Новая дорожная карта» — дизайн

Дата: 19.11.2026. Статус: реализована 19.11.2026 (выкладка — готовой сборкой, как в ФинПанели; команды плагина — /roadmap:new-roadmap и /roadmap:update-roadmaps).

## Цель

Руководитель (любой участник `finguin-agency`) одной командой в Claude Code
создаёт дорожную карту для своего финдиректора и клиента: приватный
репозиторий на корпоративном GitHub, своя база, сайт в команде Vercel
`finguin`, ссылка в ответе. Второй командой он подтягивает свежую версию
дорожной карты во все свои карты. Схема — по аналогии с ФинПанелью
(`finguin-agency/finpanel` → `finguin-agency/soft-<клиент>`).

## Как это выглядит у руководителя

1. Один раз вставляет в Claude Code сообщение из инструкции:
   «Установи плагин дорожной карты» + две команды
   `claude plugin marketplace add finguin-agency/claude-plugins` и
   `claude plugin install roadmap@finguin`. После перезапуска сессии в меню
   `/` есть `/new-roadmap` и `/update-roadmaps`.
2. `/new-roadmap` → Claude спрашивает название клиента («Ромашка»),
   предлагает латинское имя (`romashka`) — подтвердить или поправить.
3. Дальше без вопросов: репозиторий, ключи, база, выкладка. В конце —
   ссылка на сайт, пароль вкладки «Руководителю», адрес репозитория.
4. Вышло обновление у владельца → `/update-roadmaps`: свежий код уходит во
   все карты этого руководителя, данные клиентов не трогаются. В конце —
   список: обновлена / уже свежая / не обновилась и почему.

| Копия клиента | `finguin-agency/roadmap-<имя>`, приватная, с полной историей главной версии |

| Сайт клиента | команда Vercel `finguin`, проект `roadmap-<имя>` |

Чья карта: у репозитория клиента темы (topics) `roadmap` и
`lead-<логин GitHub руководителя>`.

## Компоненты

### 1. Плагин `roadmap` в `finguin-agency/claude-plugins`

```
.claude-plugin/marketplace.json      магазин «finguin», один плагин roadmap
plugins/roadmap/
  .claude-plugin/plugin.json
  skills/new-roadmap/SKILL.md        маршрут: спросить имя → запустить скрипт → показать итог
  skills/update-roadmaps/SKILL.md    маршрут: запустить скрипт → показать итог
  scripts/new-roadmap.mjs            вся работа создания (Node 22, через gh и git)
  scripts/update-roadmaps.mjs        вся работа обновления
  scripts/lib.mjs                    имя → латиница, проверки, вызовы gh
  scripts/*.test.mjs                 node:test
README.md                            инструкция для руководителей (текст для вставки)
```

Навыки короткие: вся логика — в скриптах, чтобы результат не зависел от
модели. Текст навыков и вывод скриптов — по-русски.

### 2. `new-roadmap.mjs <название> [--имя <латиница>]`

По шагам, каждый повторяемый (запуск после сбоя продолжает, а не дублирует):

1. Проверки: `gh` вошёл, пользователь — участник `finguin-agency`, имя
   латиницей `[a-z0-9-]`, репозитория `roadmap-<имя>` ещё нет (есть и он
   этого руководителя — продолжить с недоделанного шага; чужой — стоп).
2. Копия: `git clone` главной версии во временную папку → `gh repo create
   finguin-agency/roadmap-<имя> --private` → `git push` всей истории `main`.
   Темы `roadmap`, `lead-<логин>`; описание — название клиента.
3. Ключи: `gh workflow run vercel-key.yml --repo finguin-agency/finpanel
   -f repo=roadmap-<имя> -f neon=true` и ожидание, пока секреты появятся.
4. Настройки репозитория (переменные): `VERCEL_ORG_ID`, `NEON_ORG_ID`
   (номера команды Vercel и организации Neon — из `config.mjs` плагина),
   `CLIENT_NAME`, `CONTROL_PASSWORD` — случайный, 12 символов, ставится
   один раз (переменная, а не секрет: повтор и «напомни пароль» его
   показывают), последней — `ROADMAP_DEPLOY=on`.
5. Запуск выкладки (`gh workflow run deploy.yml`), ожидание
   (`gh run watch`), чтение адреса сайта из журнала, проверка
   `<адрес>/api/health` — база отвечает.
6. Итог: адрес сайта, пароль «Руководителю», репозиторий.

### 3. Изменения в главной версии (`ClientsFinguin`)

- `.github/workflows/deploy.yml` — по push в `main` и вручную;
  работает, только если `vars.ROADMAP_DEPLOY == 'on'`. В самой главной
  версии переменной нет → пропуск, нынешние 6 проектов Vercel (выкладка через
  подключённый Git) живут как раньше. Шаги: установка, `pnpm test`,
  `node scripts/provision.mjs`, `vercel deploy --prod`,
  `node scripts/provision.mjs --address` (строка «Адрес сайта: …»).
- `scripts/provision.mjs` — ищет в команде проект `roadmap-<имя>`, нет —
  создаёт (Next.js, без подключения к Git). Переменные `DATABASE_URL`,
  `CONTROL_PASSWORD`, `CLIENT_NAME` ставит, только если их нет — ручные
  правки в Vercel не перетираются. Нет `DATABASE_URL` — ищет в организации
  Neon проект `roadmap-<имя>`, нет — создаёт, берёт строку через пул.
- `lib/store.ts` — при первом заполнении базы стартовыми данными
  `clientName` берётся из `CLIENT_NAME`, если переменная есть. Остальные
  стартовые данные — прежние демо (как у всех нынешних карт).
- README — раздел «Карта для нового клиента».

Имя проекта берётся из имени репозитория (`GITHUB_REPOSITORY`), отдельно
не настраивается.

### 4. Раздатчик ключей (`finguin-agency/finpanel`, `vercel-key.yml`)

Новый необязательный параметр `neon` (по умолчанию `false`). При `true`
раздатчик дополнительно кладёт секрет `NEON_API_KEY`. Для ФинПанели ничего
не меняется. В секреты шаблона добавляется `NEON_API_KEY` — ключ API
организации Neon «FINGUIN» (создаёт агент через теневой Chrome; владелец
разрешил 19.11.2026).

### 5. `update-roadmaps.mjs [--все]`

1. Список: `gh repo list finguin-agency --topic roadmap --topic
   lead-<логин>` (`--все` — все карты, для владельца).
2. Для каждой: клон во временную папку → `git fetch` главной версии →
   `git merge --ff-only`; не вышло — обычное слияние; конфликт — отменить,
   записать «не обновлена: в копии правили код, файлы …», к следующей.
3. `git push` от имени руководителя — push запускает выкладку (push ключом
   Actions новых запусков не порождает и не может менять файлы
   `.github/workflows`, поэтому обновление идёт с компьютера руководителя).
4. Ожидание выкладок, итоговая таблица: карта, результат, адрес.

Данные клиентов лежат в базе Neon — код их не затрагивает.

## Ошибки

- Нет `gh` / не вошёл / не в организации — одна строка, что сделать
  (ссылка на приглашение), стоп.
- Раздатчик не положил ключ за 2 минуты — показать ссылку на запуск в
  Actions, предложить повторить; репозиторий остаётся, повтор продолжит.
- Выкладка упала — последние строки журнала и ссылка на запуск; повтор
  `/new-roadmap` с тем же именем продолжит с выкладки.
- Имя занято в Vercel (адрес `roadmap-<имя>.vercel.app` чужой) — Vercel
  выдаёт другой адрес; берём фактический из журнала.

## Риски (приняты, как в ФинПанели)

- Кто может писать в `finpanel`, может достать общие ключи (README
  ФинПанели, «Риск принят»). Ключ Neon добавляет к этому доступ к базам
  всех клиентов в организации Neon. Закрывается тарифом GitHub Team.
- Минуты Actions общие на организацию (2000/мес); выкладка дорожной карты
  — оценка 2–3 минуты.

## Проверка

- Модульные тесты скриптов плагина (`node --test`): латиница из
  названия, проверка имени, разбор вывода `gh`, решение «продолжить или
  стоп».
- `pnpm test` главной версии — тест на `CLIENT_NAME` при первом заполнении.
- Сквозная проверка: `/new-roadmap` для тестового клиента `plugin-test`
  → сайт открывается, `/api/health` — база отвечает, пароль подходит;
  правка в главной версии → `/update-roadmaps` → правка на сайте, данные на
  месте. После — удалить тестовые репозиторий, проект Vercel и проект Neon.
- Установка плагина с нуля по инструкции из README в чистой сессии.

## Не входит

- Перенос нынешних карт (`roadmap`, `clients4`, … и карты других
  руководителей) в новую схему.
- Codex: плагин — для Claude Code.
- Пустая стартовая карта вместо демо-данных.
